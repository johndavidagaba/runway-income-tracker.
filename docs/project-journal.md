## Week 6

### Worked on
- Picked the product for the Founder track: an irregular income/expense tracker for freelancers and side-hustlers
- Wrote the PRD, defining the MVP as three core flows: log income, log expense, see runway
- Set up the README as a living case study
- Applied Day 15–17 design system learning (color roles, tokens) toward the app's own UI

### Chose
- Decision: MVP shows one core insight — "runway" (days of spend left at current rate) — instead of a full budgeting suite
  Why: Generic budgeting tools assume a steady paycheck; runway is the number an irregular earner actually needs and no other app surfaces by default
- Decision: local-only storage for V1, no backend database yet
  Why: Cross-device sync isn't needed to validate whether the core insight is useful; adding a backend now would be solving a problem I don't have yet

### Parked
- Parked: income forecasting/prediction
  Why (and when to revisit): predicting irregular income is easy to get wrong and could mislead users about their money — revisit only after the core flows are validated with real users
- Parked: budgets/category caps, multi-currency, recurring auto-entries
  Why (and when to revisit): V2 features, not needed to test the core hypothesis
